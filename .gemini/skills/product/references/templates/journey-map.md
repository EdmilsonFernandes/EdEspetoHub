## Guidelines for Journey Mapping

### When to Create Journey Maps

- Understanding current state (as-is)
- Designing future state (to-be)
- Identifying pain points
- Aligning team on user experience
- Prioritizing improvements

### Journey Map Components

| Component | Purpose |
|-----------|---------|
| **Stages** | Major phases of the journey |
| **Actions** | What users do at each stage |
| **Touchpoints** | Where/how interaction happens |
| **Thoughts** | User's internal dialogue |
| **Emotions** | Feelings at each stage |
| **Pain Points** | Frustrations and obstacles |
| **Opportunities** | Potential improvements |

### Tips for Each Component

**Stages**:
- 4-7 stages typically
- Clear beginning and end
- Named from user's perspective

**Actions**:
- Observable behaviors
- Specific, not generic
- Include workarounds

**Touchpoints**:
- All channels (app, web, email, phone, in-person)
- Include third-party touchpoints
- Note handoffs between touchpoints

**Thoughts**:
- Based on research quotes
- Capture uncertainty and questions
- Show decision-making process

**Emotions**:
- Use consistent scale
- Based on research, not assumptions
- Capture highs and lows

**Pain Points**:
- Specific, not vague
- Include severity
- Connect to business impact

**Opportunities**:
- Actionable improvements
- Tied to specific pain points
- Vary in size/effort

### Common Mistakes

1. **Too generic**: Make it specific to a persona and scenario
2. **Assumptions**: Base on research, not guesses
3. **Inside-out view**: Focus on user experience, not internal processes
4. **Too detailed**: Keep it scannable and useful
5. **One and done**: Update as you learn more

### Using Journey Maps

- Share with stakeholders for alignment
- Reference in sprint planning
- Guide design decisions
- Prioritize backlog items
- Measure improvement over time
